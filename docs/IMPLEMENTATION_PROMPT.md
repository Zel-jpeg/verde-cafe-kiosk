Treat the sample UI PDF as visual inspiration, not a required pixel-for-pixel design. The target deployment is Vercel.

Study their hierarchy and interaction patterns: a bright, uncluttered POS canvas; easy-to-scan category controls and photo-led product cards; a persistent order/cart area with a prominent total and checkout action; simple payment success feedback; and a tidy admin menu layout. Adapt those ideas to Verde Café branding, Philippine peso amounts, and the exam's required customer journey. Do not copy their other brands, French text, exact artwork, sample prices, or unrelated restaurant features.

**Objective:**
Build a complete, runnable customer kiosk and protected admin panel in **React + TypeScript + Vite**, backed by **TypeScript Vercel Functions** and **Supabase Auth, Postgres, and Storage**. Use custom CSS for a polished Verde Café touch interface; Tailwind is optional if it helps. The customer route is `/` and the admin route is `/admin`.

**Requirements:**
1. Implement the entire customer journey: at least six product cards with names, prices, and images/placeholders; add, increase, decrease, and remove cart lines; accurate subtotals and total; Order Summary with Back preserving the cart; large Cash, QR Payment, and Credit/Debit Card choices; payment processing; success with a unique reference; digital receipt; and New Transaction clearing all customer state. QR and Card are explicitly simulations. Cash accepts exact or greater payment, calculates change, and rejects blank, invalid, negative, or insufficient amounts without saving a transaction.
2. Use integer centavos for money. The checkout API must reload current product prices and stock from Supabase, reject empty/invalid orders and unavailable stock, and ignore browser-submitted prices or totals. Save a completed transaction, immutable item snapshots, and stock deductions in one atomic database operation. Prevent concurrent overselling and duplicate deductions on a retry using an idempotency key. Failed or incomplete payments must leave stock and transaction records unchanged.
3. Provide Supabase Auth sign-in for admins, with no public admin self-registration. Verify each admin API request's access token and server-managed admin role before product or image reads/writes. A React route guard alone is insufficient. Admins can list, add, edit, and archive products; set name, positive price, nonnegative integer stock, active status, optional category/description, and image. Out-of-stock and archived items cannot be purchased. Preserve historical receipt snapshots when catalog data changes.
4. The admin image picker must accept **PNG or JPEG**. In the browser, decode and proportionally resize to at most **1200 px** on the longest side, without upscaling; encode to **WebP** (start near quality `0.82` and adjust if needed). Reject input over **10 MiB**, failed conversion, a non-WebP result, or WebP output over **1 MiB**. Preview the converted file. Upload only the WebP Blob through an authenticated admin API. The API rechecks admin role, MIME, WebP signature, size, and a safe generated `.webp` path. Store the file in a public-read Supabase Storage `product-images` bucket limited to `image/webp` and **1 MiB**; store only its object path in the `products` row. Handle replacements without leaving a broken product image. Show images on the customer catalog.
5. Include SQL migrations and seed data for `products`, `transactions`, `transaction_items`, `user_roles`, constraints, RLS/grants, an atomic checkout database function or equivalent, and the Storage bucket/policies. Document secure creation of the first admin account and role assignment. The browser may use only `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` for Auth. Keep `SUPABASE_URL` and `SUPABASE_SECRET_KEY` in server environment variables. Never authorize with client-editable user metadata.
6. Initialize/scaffold the React + TypeScript + Vite application **in this repository root**; create the needed `package.json`, lockfile, TypeScript/Vite configuration, source folders, and Vercel API files rather than assuming a template already exists. Follow `docs/PROJECT_STRUCTURE.md` as the initial folder guide. Include React Router, typed API calls, reusable components, accessible touch targets, responsive layout, loading/error/success feedback, and existing Verde Café branding. Use the five reference images to guide spacing, product-card composition, category navigation, order summary, and success/admin views while preserving the specified functionality. Configure Vercel so direct `/admin` visits load the SPA while `/api/*` still reaches Functions. Create `.env.example` with every required variable and placeholder values, make sure `.env` and `.env.local` are ignored by Git, and provide run/build/test scripts plus verified local and Vercel setup instructions in `README.md`. If valid Supabase values are securely available in the working environment, configure an ignored local `.env.local`; otherwise leave actual secrets for the user to supply and list the exact variables needed.
7. Verify with focused automated tests for money, checkout/stock/idempotency, authorization, and image validation where practical. Run the build and the 15 instructor cases, 26 checklist rows, and group-specific cases in `docs/ACCEPTANCE_TESTS.md`. Record actual results and remaining issues; do not mark unrun checks as passed.

**Constraints:**
Use the selected TypeScript/React/Vite/Vercel/Supabase stack; do not introduce PHP or Laravel. Keep the customer kiosk public and the admin panel protected by server checks. Never collect real card numbers, CVV, or payment credentials, and never claim a simulated payment is live. Do not commit `.env` files, secrets, PDF reference files, reference images, or generated uploads unless explicitly requested. If the five images are inaccessible in the coding environment, ask for them to be attached there before making final visual decisions. Do not invent test results, deployment success, or group contribution evidence. Preserve existing branding and relevant repository work. If a Supabase project, keys, or Vercel access is unavailable, implement the source and migrations, identify the exact configuration needed, and clearly report what could not be verified.

**Expected output:**
Deliver the runnable project files, SQL migrations/seed, `.env.example`, updated setup and deployment documentation, and a concise report of files changed, architecture choices, commands run, test results, and any manual Supabase/Vercel steps. Show the customer flow and admin/image flow working locally when credentials are available; otherwise state the precise verification limit. Keep changes reviewable and do not push or deploy unless explicitly requested.
